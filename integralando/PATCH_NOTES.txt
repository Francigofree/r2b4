R2B4 async L6 monotonic handoff P0
Base: 3236cada2eb12b7f63944ffa1fc55c47b39ae8be

Root cause
----------
Freshness used monotonic_ns while handoff eligibility used a fixed tick count.
Runtime jitter therefore delayed visibility of ready plans and could make the
currently accepted plan stale before the release tick.

Non-invasive resolution
-----------------------
1. Add optional AsyncL6PlannerConfig.release_delay_ns.
2. Current live config sets 100 ms.
3. New requests store exactly one handoff criterion:
   - new mode: pending_release_not_before_ns
   - legacy mode: pending_release_tick_id
4. New mode accepts on the first closed tick at/after the monotonic threshold.
5. Async new-mode replanning uses the existing real-time replan interval only;
   the historic min-tick-gap remains for synchronous and legacy replay.
6. Keep max_plan_age_ns at 350 ms.
7. Preserve old typed capture replay through default-None new fields.
8. Update only the exact V3 contract sentence required by this semantic change.
