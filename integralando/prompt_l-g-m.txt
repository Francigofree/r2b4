# Globális javítási terv

A célhoz a jó megoldás **nem a `max_position_variance` lazítása és nem további Room Cruise / FP kivételek beépítése**.

A rendszerben jelenleg ugyanaz a live EKF-pose az SSOT a publikus pozícióhoz és a `RollingLocalMap`-hez, miközben gyakorlatilag minden komolyabb mozgás ugyanabba a közös motion/safety láncba fut. :chatgpt-content-reference{index="0"} A Follow Person is ugyanazt a local rollout/costmap útvonalat használja, amikor ténylegesen haladnia kell. :chatgpt-content-reference{index="1"}

Ezért a javítást **L3→L4→L6→L9 rendszer-szinten** kell megcsinálni.

> Fontos korlát: fizikailag nem garantálható, hogy a robot minden környezetben „soha ne veszítse el” a globális pozícióját. A garantálható rendszer-viselkedés az, hogy **a globális pozíció romlása ne tegye tönkre a lokális mozgást; a lokális pozíció minőségének romlása ne maradjon észrevétlen; és a robot ne mozogjon úgy, hogy ezzel tovább rontsa a lokalizációt.**

---

# 1. Az alapvető architekturális változás: két pose-frame

A jelenlegi egyetlen pose fogalmát ketté kell választani:

```text
                        ┌─────────────────────────┐
encoder + IMU ────────► │ LOCAL ODOMETRY          │
                        │ R2B4_ODOM_LOCAL          │
                        │                          │
                        │ folyamatos               │
                        │ nem ugrik                │
                        │ rövid távon pontos       │
                        └───────────┬─────────────┘
                                    │
                                    │ map→odom transform
                                    ▼
LiDAR matcher ────────► ┌─────────────────────────┐
                        │ GLOBAL LOCALIZATION      │
                        │ R2B4_BOOT_ROBOT_MAP      │
                        │                          │
                        │ abszolút x/y/yaw         │
                        │ driftet korrigál         │
                        │ relokalizálható          │
                        └─────────────────────────┘
```

Ez a javítás központi eleme.

## `local_pose`

Feladata:

- pillanatnyi robotmozgás;
- local planner;
- obstacle avoidance;
- RollingLocalMap;
- FP;
- Room Cruise;
- relative movement;
- trajectory execution.

Tulajdonsága:

**nem szabad ugrania akkor sem, ha a globális LiDAR lokalizáció korrigálja magát.**

## `global_pose`

Feladata:

- abszolút `NAVIGATE`;
- globális célok;
- tartós coverage;
- room/global memory;
- későbbi szemantikus térkép;
- abszolút helyhez kötött taskok.

A LiDAR matcher korrigálhatja.

# 2. Ez oldja meg a mostani alapkonfliktust

Jelenleg:

```text
LiDAR global localization romlik
              ↓
EKF Pxx/Pyy nő
              ↓
ugyanaz a pose szolgál
   ├─ local mapnek
   ├─ local plannernek
   ├─ Room Cruise-nak
   ├─ FP-nek
   └─ global NAVIGATE-nek
              ↓
L9 dilemma:
STOP vagy veszélyes bypass
```

Ezért jött létre a mostani problémás:

```python
requires_global_position = False
```

A dual-frame rendszer után:

```text
GLOBAL localization romlik

global_pose:
DEGRADED
   │
   ├── NAVIGATE global cél → reacquire / korlátozás
   │
   └── tartós map learning → pause
       
local_pose:
GOOD
   │
   ├── Room Cruise → MEHET
   ├── Follow Person → MEHET
   ├── relative move → MEHET
   └── obstacle avoidance → MEHET
```

Vagyis **nem kell sem vakon megállni, sem vakon figyelmen kívül hagyni a covariance-t.**

# 3. Új L3 contract: `LocalizationQuality`

A lokalizáció állapotát **L3-nak egyszer kell kiszámolnia**.

Nem L6-nak kell eldöntenie, hogy jó-e a pose.

Javasolt contract:

```python
@dataclass(frozen=True)
class LocalizationQuality:
    local_translation: QualityState
    heading: QualityState
    global_position: QualityState

    local_sigma_m: float
    global_sigma_m: float
    yaw_sigma_rad: float

    encoder_age_ns: int
    imu_age_ns: int
    lidar_age_ns: int
    global_fix_age_ns: int

    local_pose_continuous: bool
    pose_discontinuity: bool

    lidar_relative_consistency_m: float | None
    encoder_lidar_consistency_m: float | None

    generation: int
```

Állapot:

```python
class QualityState(Enum):
    GOOD = ...
    DEGRADED = ...
    LOST = ...
```

És a `RobotEstimate` mellett:

```text
StateEstimate
 ├─ local_pose
 ├─ global_pose
 ├─ map_to_odom
 └─ localization_quality
```

Ez legyen az SSOT.

---

# 4. Nem elég Pxx/Pyy

Ez különösen fontos.

A jelenlegi `max_position_variance = 0.25` egyetlen abszolút covariance-kapu. A production configban valóban ilyen operációs limit szerepelt. :chatgpt-content-reference{index="2"}

De például:

```text
globális bizonytalanság: 1.5 m
lokális relatív hiba az elmúlt 1 s alatt: 2 cm
```

esetén Room Cruise szempontjából a robot tökéletesen használható.

Fordítva:

```text
globális covariance: még 0.20
encoder megcsúszott
lokális relatív hiba: 25 cm
```

esetén a robotnak **nem szabad haladnia**.

Ezért:

```text
Pxx/Pyy != local motion quality
```

---

# 5. Új motion requirement contract

A mostani:

```python
requires_global_position: bool
```

helyett:

```python
@dataclass(frozen=True)
class LocalizationRequirement:
    local_translation: bool
    heading: bool
    global_position: bool
```

## Példák

| Mozgás | Local XY | Heading | Global XY |
|---|---:|---:|---:|
| Room Cruise | igen | igen | nem |
| Follow Person haladás | igen | igen | nem |
| Face Person, csak forgás | nem | igen | nem |
| TURN_BY | nem | igen | nem |
| MOVE_RELATIVE | igen | igen | nem |
| NAVIGATE abszolút cél | igen | igen | igen |
| TELEOP előre | igen* | igen | nem |
| STOP | nem | nem | nem |

A `*` itt azt jelenti, hogy a motor fizikailag mozoghatna lokalizáció nélkül is, de **ha a cél a pose megőrzése**, minden transzlációt local-pose quality gate alá kell tenni.

---

# 6. L9 legyen képességkapu, ne mode-kivétel

L9 jelenlegi logikáját át kell alakítani.

Nem:

```python
if requires_global_position:
    check_position_variance()
```

hanem:

```python
if abs(v) > EPS:
    require(local_translation >= required_quality)

if abs(omega) > EPS:
    require(heading >= required_quality)

if intent.localization_requirement.global_position:
    require(global_position >= required_quality)
```

Így még akkor sem tud egy hibás L6 producer veszélyesen mozgatni, ha rossz requirementet ad.

### Defense in depth

Az intent például mondhatja:

```text
global_position=False
```

de ha:

```text
v != 0
```

akkor L9 **automatikusan követelje meg a local translation quality-t**.

Ez nagyon fontos P0 tulajdonság.

# 7. L4 RollingLocalMap átállítása local frame-re

Ez a második kulcsfontosságú módosítás.

A jelenlegi rendszerben a raw scan + live EKF pose táplálja a `RollingLocalMap`-et. A matcher localization map és a RollingLocalMap helyesen két külön rendszer. :chatgpt-content-reference{index="3"}

Ezt a szeparációt meg kell tartani.

Viszont:

```text
RollingLocalMap
```

ne a global map frame-ben tárolja a rövid életű akadályokat.

Új:

```text
frame_id = R2B4_ODOM_LOCAL
```

Transform:

```text
LiDAR robot-frame
      ↓
measurement-time local_pose
      ↓
R2B4_ODOM_LOCAL
      ↓
RollingLocalCostmap
```

Így egy global relocalization:

```text
map pose correction = 0.8 m
```

nem mozgatja el hirtelen a robot előtt álló széket 0.8 méterrel.

# 8. A globális és lokális térképet továbbra sem szabad összevonni

Maradjon:

```text
LiDAR
 ├── localization map
 │      └── globális localization
 │
 └── RollingLocalMap
        └── local obstacle/navigation
```

A jelenlegi rendszerben sincs `RollingLocalMap → matcher` adatél, és ezt meg kell tartani. :chatgpt-content-reference{index="4"}

Csak a frame-t kell szétválasztani.

# 9. Follow Person

FP-nél ez különösen fontos.

A jelenlegi FP akkor, amikor messze van és haladnia kell:

```text
person
 ↓
local_goal
 ↓
54 trajectory candidate
 ↓
normal rollout
 ↓
MotionRealizer
```

:chatgpt-content-reference{index="5"}

Tehát FP-t sem szabad globális pose-ra építeni.

## Helyes FP adatút

```text
camera detection
       ↓
robot-relative person observation
       ↓
R2B4_ODOM_LOCAL track
       ↓
local goal
       ↓
local planner
       ↓
motion
```

A globális pozíció akár LOST lehet.

FP továbbra is működhessen:

```text
global_position = LOST

→ FOLLOW_PERSON ALLOW
```

# 10. Room Cruise

Ugyanez.

Room Cruise coverage-jét ketté kell választani:

### Rövid távú coverage

```text
local coverage
local goal
obstacle history
stuck detection
```

→ `R2B4_ODOM_LOCAL`

### Hosszú távú coverage

```text
melyik szobában járt
tartós visit map
globális route memory
```

→ `R2B4_BOOT_ROBOT_MAP`

Csak akkor frissülhet, ha:

```text
global_position == GOOD
```

Global localization romlásakor:

```text
local Room Cruise: folytatódik
global memory write: szünetel
```

Ez megakadályozza, hogy rossz globális koordináták tartósan beszennyezzék a térképet.

---

# 11. A lokalizációt nem csak figyelni kell — védeni is kell

A célod szempontjából ez a harmadik nagy elem.

A mozgásvezérlésnek figyelembe kell vennie, hogy **maga a mozgás ronthatja a localizationt**.

Például:

- túl nagy sebesség;
- agresszív pivot;
- nagy gyorsulás;
- wheel slip;
- hosszú featureless folyosó;
- LiDAR scan közbeni nagy yaw;
- kevés geometriai struktúra.

Ezért L6 planner kapjon:

```text
localization_quality
```

és ne csak:

```text
progress
clearance
smoothness
novelty
```

alapján döntsön.

---

# 12. Új planner-komponens: localization preservation

Nem feltétlenül új teljes score kell első körben.

Először elég adaptív limit:

```text
quality GOOD
    → normál v / omega

quality DEGRADED
    → v_max csökkentés
    → omega_max csökkentés
    → acceleration csökkentés

quality CRITICAL
    → translation = 0
    → controlled reacquire rotation

quality LOST
    → STOP / bounded recovery
```

Tehát nem:

```text
GOOD → MOVE
BAD  → STOP
```

hanem:

```text
GOOD
 ↓
DEGRADED
 ↓
RECOVERY
 ↓
GOOD
```

Ez a folyamatos mozgás egyik kulcsa.

---

# 13. Külön localization recovery state machine

Javasolt állapotgép:

```text
TRACKING
   │
   ├── global romlik
   ▼
GLOBAL_DEGRADED
   │
   │ local pose továbbra GOOD
   │
   ├──────────────► normál local motion lassítva
   │
   └──────────────► background global reacquire
                           │
                           ▼
                        TRACKING
```

Ha local is romlik:

```text
LOCAL_DEGRADED
       │
       ▼
REACQUIRE
       │
       ├── slow pivot / small arc
       ├── fresh LiDAR
       ├── matcher verification
       └── no forward translation
       │
       ▼
TRACKING
```

Ha recovery sikertelen:

```text
LOST
 ↓
STOP
```

A kontrollált pivot csak akkor engedélyezhető, ha:

- yaw minőség megfelelő;
- friss raw LiDAR van;
- L12 clearance megfelelő.

# 14. Relokalizációkor ne ugorjon a lokális világ

Ez a dual-frame legfontosabb következménye.

Példa:

```text
robot local:
odom x = 5.20 m

matcher rájön:
global x nem 7.3,
hanem 6.4
```

Ne ez történjen:

```text
robot local pose:
5.20 → 4.30   ← TILOS
```

Hanem:

```text
local pose:
5.20 → 5.20

map_to_odom:
korrekció -0.90 m
```

Így:

- motor control nem ugrik;
- FP nem ugrik;
- local goal nem ugrik;
- obstacle map nem ugrik;
- Room Cruise nem ránt egyet.

Csak a globális koordinátarendszer kapcsolata változik.

# 15. NAVIGATE kezelése

Global NAVIGATE speciális.

Normál:

```text
global target
     ↓
map_to_odom
     ↓
local target
     ↓
local planner
```

Ha a global localization romlik:

```text
global target
     ↓
nem megbízható transform
```

Ilyenkor:

```text
NAVIGATE
→ local forward progress freeze
→ reacquire
→ map_to_odom frissítés
→ target újratranszformálás
→ replan
→ continue
```

Nem kell missiont megszakítani.

---

# 16. Uncertainty-t ne csak STOP-ként használjuk

Ez tovább javítja a folytonosságot.

A local covariance használható obstacle inflationre:

```text
effective obstacle radius =
physical radius
+ normal safety margin
+ localization uncertainty
```

Például elvi formában:

```text
uncertainty_margin = K * local_sigma_xy
```

Minél bizonytalanabb a local pose:

- nő a footprint;
- csökken a sebesség;
- csökken a usable corridor;
- végül természetesen nincs biztonságos trajectory.

Ez sokkal jobb, mint:

```text
variance 0.249 → teljes sebesség
variance 0.251 → STOP
```

# 17. L3-ban kötelező input freshness

Ez P0.

Korábbi source audit már talált olyan állapotot, ahol változatlan IMU-minta 480 ms után is ALLOW állapotig eljutott, bár a measurement admission limit 250 ms volt. :chatgpt-content-reference{index="6"}

Ezért a `LocalizationQuality` nem támaszkodhat pusztán device healthre.

Kell:

```text
encoder_measurement_age
imu_measurement_age
lidar_measurement_age
matcher_result_age
```

és **consumer-side freshness**.

Ha például:

```text
IMU health = OK
IMU age = 500 ms
```

akkor:

```text
heading quality != GOOD
```

# 18. Relatív lokalizáció mérés

Ez az a rész, ami a mostani patchből hiányzik.

A local translation quality-t nem lehet pusztán az absolute EKF covariance-ból képezni.

Legalább:

```text
encoder predicted Δpose
        │
        ├──────────┐
        ▼          ▼
 IMU Δyaw      LiDAR relative Δpose
        │          │
        └────┬─────┘
             ▼
     consistency monitor
```

Kimenet:

```text
Δtranslation disagreement
Δyaw disagreement
slip suspicion
local relative covariance
```

### P1-ben

A meglévő LiDAR matcherből érdemes külön kivenni:

```text
relative motion quality
```

nem csak:

```text
absolute map match result
```

Hosszabb távon pedig célszerű saját rövid életű local submap registration.


A réteg-hozzárendelést a jelenlegi diagnosztikai forrás is így kezeli. :chatgpt-content-reference{index="7"}

P0:

1. `requires_global_position` boolean megszüntetése.
2. `LocalizationRequirement` 3 komponenssel.
3. `LocalizationQuality` SSOT L3 output.
4. consumer-side encoder/IMU/LiDAR freshness.
5. L9 automatikusan local translationt követel minden `v != 0` esetben.
6. yaw quality minden `omega != 0` esetben.
7. absolute XY csak abszolút targethez.
8. jelenlegi `position_variance=4.0 → EXPLORE automatikusan ALLOW` acceptance teszt eltávolítása.
9. L12 teljesen változatlan, továbbra is független final safety.

### P0 után

Még nem kész a teljes rendszer, de a mostani veszélyes logikai rés megszűnik.

# 22. Kötelező tesztek

Nem elegendő az:

```text
robot nem állt meg
```

acceptance.

## A. Global localization loss

Injektálás:

```text
global Pxx/Pyy ↑
local odometry healthy
```

Elvárt:

```text
Room Cruise → CONTINUE
FP → CONTINUE
relative move → CONTINUE

NAVIGATE → REACQUIRE / HOLD
```

---

## B. Local odometry loss

```text
encoder inconsistency / slip
global matcher még látszólag jó
```

Elvárt:

```text
translation → STOP/RECOVERY
```

Nem szabad a global pose-nak elfednie.

---

## C. Global relocalization jump

Injektált korrekció:

```text
+0.8 m x
-0.4 m y
```

Elvárt:

```text
local_pose discontinuity = 0
RollingLocalMap discontinuity = 0
motor command spike = 0
FP target local jump = 0
```

Csak:

```text
map_to_odom
```

változhat.

---

## D. Slow encoder drift

Ez a kritikus teszt a korábbi javítás hiányára.

```text
+1–2% artificial distance drift
```

több tíz másodpercen keresztül.

A rendszernek észlelnie kell az:

```text
encoder ↔ LiDAR relative inconsistency
```

növekedését.

---

## E. IMU stale

Az IMU értéke változatlan marad.

Elvárt:

```text
heading quality DEGRADED/LOST
```

nem pusztán:

```text
device health OK
```

---

## F. FP global-loss

Haladó FP közben:

```text
global localization → LOST
```

Elvárt:

```text
person tracking continuous
local trajectory continuous
motor command continuous
```

---

## G. Room Cruise 10+ perc

Nem 60 s.

Mérendő:

```text
local relative drift
global covariance
matcher success
matcher rejection
relocalization count
local pose discontinuities
map discontinuities
stop count
false localization stop
coverage
encoder/LiDAR consistency
```

# 23. Acceptance kritérium

A teljes fejlesztés akkor tekinthető késznek, ha teljesül:

```text
GLOBAL pose romolhat
        ↓
LOCAL mozgás ettől nem romlik
```

és:

```text
LOCAL pose romlik
        ↓
rendszer észleli
        ↓
lassít / reacquire
        ↓
nem épít rossz térképet
        ↓
nem növeli tovább kontrollálatlanul a hibát
```

valamint:

```text
global relocalization
        ↓
nem okoz local pose jumpot
        ↓
nem okoz trajectory jumpot
        ↓
nem okoz motor command spike-ot
```
